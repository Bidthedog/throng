# Writing throng's user guide

The guide teaches **tasks**. Each page is one area of work; each `##` section is one thing a user does,
headed in their words, with numbered directions. Facts (every setting, binding and theme setting) live in
the three reference pages, which throng-docs owns; the guide links to them and never copies their tables.

## Where things live

| Thing | Path |
|---|---|
| Pages | `site/guide/<slug>.md` — `index.md` is the start page, `quick-start.md` the tour, `faq.md` questions |
| Images | `site/guide/images/<page>/<task>.png`, generated by `npm run guide:screenshots`, never hand-edited |
| Screenshot cases | `packages/ui/tests/guide-screenshots/guide-screenshots.spec.ts` |
| Which screen each shows | `site/guide/images/screens.json`: every image names the source folders and files of its screen; `npm run guide:screens-stale -- --since <ref>` lists images whose screen changed since `<ref>` while the image did not (080 FR-067) |
| The map | `packages/core/src/help/guide-map.ts` — `GUIDE_PAGES`, `GUIDE_MAP`, `GUIDE_EXCLUSIONS` |
| Help URLs | `packages/core/src/help/help-urls.ts` — the only place a guide URL is written |
| The builder | `scripts/guide-build.mjs`, run by `scripts/site.mjs`; preview with `npm run site:preview` |
| Voice, page layout, callouts | [references/style.md](references/style.md) |

## Writing or rewriting a page

1. Read [references/style.md](references/style.md) and one finished page (`site/guide/terminals.md`) first.
2. Keep every `##` heading that exists: the app, the (?) links and the release notes link to it. A
   heading that must change gets the same change in `GUIDE_MAP` (`task` text and `anchor`).
3. Every task: a bold breadcrumb, a prose description, numbered steps, at most one callout (080 FR-059),
   written by the **stop-slop** skill's rules.
4. Link settings, bindings and theme settings to their reference section by key; never restate values.
5. Add a screenshot case for any task that teaches a part of the window, run the generator, and place
   the image after the step it shows. Give the new image its entry in `screens.json` (`guide-screens-stale.test.ts`
   fails on an image with none).
6. Preview with `npm run site:preview`, then run
   `npx vitest run --project unit packages/ui/tests/unit/docs-currency.test.ts`.

## Checks that will fail, and what they mean

| Failure | Fix |
|---|---|
| `docs-currency.test.ts`: a command, panel type or preview type is uncovered | Add it to a task's lists, or exclude it with a reason |
| Map ↔ page mismatch | The heading text and the map's `task` and `anchor` must agree |
| Task layout | A task section lacks its Where line, Why line or numbered steps |
| No screenshot | A page other than `index` and `faq` shows no image from `images/<page>/` |
| Outline page | `status: outline` in front matter — every page ships complete |
| Built-anchor test | A link, a map entry or a (?) targets an id the built site lacks |
